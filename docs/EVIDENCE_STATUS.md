## 下一步的优先顺序

1. 完成 MuSiQue 固定流程与标注支持材料诊断的可执行协议、预算和离线验收。
2. 新范围获准后进行真实小面板校准；冻结结果后分别检查答案 F1、支持段覆盖、交付率与成本。
3. 依据检索→入窗→阅读→综合的实际损失，只修主导环节；不同时换模型、检索、状态和主评分。
4. 确认存在可修复差距后开展真实代码演化，比较固定／轮换模块、总分反馈与失败轨迹反馈。
5. 冻结改进后才用保留角色测泛化，再回到 BrowseComp 检查困难检索迁移。

该顺序覆盖 RAG 专用模块、LLM 决策与证据综合；经验策略的研究要等真实父子收益可测。宿主继续负责来源、隔离和预算，不把工程审核数量作为研究成功指标。

D_select / D_report 仅完成可信准备器的本地分组，未用于模型测量或选择；历史封存 Collect、Meta、Dev、Test 未动用。公开仓库无题目、参考答案或原始请求，复现效果仍需要相应本地材料及授权。
