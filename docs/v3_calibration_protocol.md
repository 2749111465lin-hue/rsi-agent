## 问题与设计

先测固定的大模型是否能沿新闭环利用桥接实体继续检索，并把找回的证据用于最终答案。暂不改程序、训练权重、启动选择器或增加审阅模型。模型驱动规划、阅读和答案综合；代码管理检索、精确引用、预算和冻结。

从旧P4已经使用的32题中，以SHA256(固定种子|题号)选8题，不按原得分、证据或答案筛选。不使用该64题来源池的剩余未用题。8题已属开发材料，本次没有独立确认的地位。保留原100,195篇完整文档库和原索引文件；不按正确证据缩小语料。

## 已纳入的修复

1. LLM提供原文引句，宿主定位唯一精确区间。重复引句需要更长的唯一引句或正确偏移；不给错误偏移自动纠错。
2. 首轮空检索时可在现有轮数内改写查询。无新查询、达到停滞限额或预算耗尽则停止，并预留最终回答。
3. 回答原文匹配、引用来源匹配和语义正确性分开。来源验证不等于事实支持验证。
4. 生成检查点绑定题号、臂、重复、节点、程序、语料和方案。完整笛卡尔积未完成、未知调用结果或源码变化时不可进入评分。

## 信息和评分边界

生成只向DeepSeek发送选中问题与实际检索得到的上下文及中间状态。候选程序、参考答案、历史gain、凭据和封存题目不进入模型输入。指定密钥仅由本机读取，不写日志、不上传Git。

生成前对本地参考文件做字节哈希，冻结身份但不解析答案。所有32个结果冻结并检查完整性后，才在本地解析参考答案。输出两份不同用途的材料：

- 本地EM/F1代理诊断、交付率、引用来源有效率、逻辑调用、物理调用和保守费用。
- 隐去臂和程序身份的回答盲评包，以及单独保留的私有映射。

BrowseComp-Plus官方使用模型裁判。本轮没有部署该裁判，EM/F1只能帮助定位明显变化；标题改写、别名、解释性答案会产生规则偏差。不能据此直接宣布官方准确率提高。没有答案的实际交付失败保留为0，缺失参考或未知API结果不能伪造0。

逐题两次结果先取均值，再比较同题两臂；统计单位是8道题，不是32个结果。结构失败计数与模型自报失败单列。检索为空只能说明该查询在该索引下为空，不等于全部证据不存在；模型说缺证据也不作为事实裁决。

## 决策

- 技术故障、调用结果未知、身份变化：停止该运行并报告已有账本；不自动追加尝试。
- 完整运行后：检查是否确实形成新查询、新证据、最终可引用证据，以及这些变化是否伴随答案变化。
- 若完整引文到达答案阶段仍无正确回答，优先检查约束核对和答案综合；若证据始终未召回，优先修改查询或检索模块。
- 本轮仅决定下一次代码改进应针对何处，不设事后可移动的“提升通过线”。要宣称质量提高，还需要固定评分后的独立题目、同预算对照。
