# 反馈与经验控制：实现及验收

日期：2026-10-09。分支：codex/v3-experience-ablation。本次复用现有ProgramDeveloper、EvolutionRunner和live_evolution入口，未另建一套搜索系统。原终答干预在独立feedback分支执行，源码和结果不变。以下仅为零外部API的工程验证，真实演化效果未验证。

## 1. 实际修复

| 原缺口 | 实现 | 边界 |
|---|---|---|
| 拒收不进入节点库，模块可能一直被当作没试过 | 每次终结提案单独记录attempt，拒收也占机会；轮换与机会覆盖可选 | 拒收不伪造节点，不当收益样本；模型结果未知时停止而不终结计零 |
| 无单模块收益时诊断先验持续锁定同模块 | 无尝试模块优先，无可归因收益时优先较少机会的模块 | 保留旧选父规则；失败修复有明确Debug例外；不承诺真实收益 |
| 已保存机制假设却未传给修改器 | 固定容量记忆可传最长1600字符假设和有符号结果 | 标为开发者推测、非因果事实；mixed只作整程序经验 |
| 仅总分对照仍经decision或memory漏入诊断 | aggregate/cases/trace严格白名单构造最终输入 | 固定父程序、固定模块指令、无记忆；F1/F2相同案例及重复 |
| 同父同输入多次提案可能命中同一回答缓存 | 每个proposal_slot使用不同宿主bank | slot不进入提示；同一次恢复不重购；未知请求先停止 |
| 输入过长时各臂裁剪共同案例不同 | 受控反馈不再裁剪，完整请求超限即拒收 | 不补足“成功候选数”；该提案仍占预算机会 |

固定模块在此是固定修改意图和指令，不是声称实际AST只改该模块。仍允许通用改写，实际范围单独验证；只有single_module给单模块收益，mixed/unknown不强行归因。反馈对照估计整个反馈条件的作用，不能因此宣称某模块的纯因果贡献。

## 2. 新入口契约

新schema为rag-rsi-live-evolution-2，必须显式给出controls。旧schema1保留原行为和bank；不重释已有冻结结果。

```json
{
  "parent_policy": "fixed_root",
  "module_policy": "fixed",
  "fixed_module": "answer_generation",
  "memory": "none",
  "feedback": "aggregate",
  "case_schedule": [{"question_id": "fixture-fit-q1", "repeat": 0}]
}
```

此例只说明字段，不是已批准真实运行方案。case_schedule必须是D_fit中预先固定的1至16个不同题号，重复编号必须存在；即使aggregate不发送案例，也使用同一冻结计划。cases增加题面、预测、逐题分；trace再加相同案例的执行轨迹。预测和分数组合可能透露可接受答案，明确记录，不冒充“零答案信息”。

rich使用原完整反馈，case_schedule为空；可独立选择none/mechanism记忆，以及adaptive父规则下的round_robin_v1或experience_coverage_v1模块策略。fixed_root目前仅与fixed模块指令组合。新schema禁止legacy策略或legacy记忆静默进入；三项研究因素需要分轮，不把全部开关同时打开后归因其中一个。

## 3. 验证

全套750项：749通过，1项需显式启用的真实WSL答案来源回归跳过。新增71项覆盖反馈隔离、终结机会计数、恢复、参数冻结、独立提案bank和旧入口兼容。完整日志及源码哈希见验证JSON。

合成的八步mixed历史中，旧策略模块覆盖为0/1/7/0；机会覆盖和轮换为2/2/2/2，父节点序列相同，模块收益样本仍为0。这里只证明摆脱该合成锁定反例，不证明经验策略优于轮换。

真实WSL脚本整链通过：5次实际隔离执行全部通过隔离、模型答案来源与引用来源检查；相同正文的两个提案使用不同bank，首个测量、第二个因重复拒收，两次机会都计入。交付锁定和报告完成，恢复新增0次调用。10次是本地脚本模型响应，外部API与真实费用均为0；合成账本费用不当作供应商费用。

## 4. 实验顺序不变

本轮96次固定终答对照已经完成，但整块删除判断未过推进条件。先据真实损失修一项RAG能力；之后另冻结反馈贡献对照，再测试经验复用和模块选择。新控制入口不意味着这些实验已经运行，也没有开启元重加权或动用封存数据。
