## 1. 结论

外部审查的主要方向成立。现在需要修的是实验输入的公平性、候选程序的接纳条件和模块经验的可信度。继续扩大同一种两臂试跑，暂时不能证明多轮检索或程序自改进有效。

首轮真实运行仍有价值：它发现了真实上下文堵点。但 `single` 的地板结果、8道已用题和单题贡献全部命中，使质量优劣无法可靠判断。首轮结果不能升级为正式 BrowseComp 成绩或 RSI 收益证据。

## 2. 本地复核得到的证据

### 2.1 字母序截断在真实运行中触发，不只是构造示例

重新检查32份冻结执行收据、97次实际搜索，未打开参考答案，未重新检索或生成回答。

| 指标 | 原问题单轮 single | 动态 loop |
| --- | ---: | ---: |
| 搜索调用 | 16 | 81 |
| 查询去重词数范围 | 50–73 | 5–26 |
| 超过60词的调用 | 8/16 | 0/81 |
| 受影响独立题目 | 4/8 | 0/8 |
| 被截去的去重词项，按调用累计 | 66 | 0 |

按题去掉两次重复后，4题共丢失33个去重词项计数。截断只发生在 FTS MATCH 表达式中；模型仍收到完整问题，片段定位也仍使用完整查询。

因此存在与臂相关的输入差异，但不能量化它损害了多少准确率。唯一两次答对的那道题只有52个去重词，没有触发截断；不能把该题胜出归因于这个缺陷，也不能把全部single弃答归因于它。

### 2.2 停滞轮数实际一致

归档默认值为1，但两臂冻结配置都显式覆盖为2；全部57次阅读请求均携带 `stop_after=2`。文档与这次实际运行一致。后续公开脱敏配置摘要，避免审阅者只能猜本地覆盖值。

### 2.3 模块标签和答案来源问题已复现

在真实WSL内使用虚构题和本地脚本模型完成复现，主源码未改动：

- 声明 `query_rewrite`、实际仅更改常量答案的提案通过，随后该收益被记入查询模块经验。
- 没有任何回答模型调用、直接返回正确常量的候选，仍取得 `score=1`、`valid_program=True`。
- 回答模型给出错误答案、程序覆盖成正确答案，仍取得同样结果。
- 上述候选的来源诊断其实已经是 `no_observed_final_answer`，但它没有参与有效程序判定。

这是研究接纳条件的缺失，不证明旧真实实验发生过这种行为。来源真实性与答案文字得分应分开保存，但无来源候选不能进入本研究的有效改进与交付集合。

### 2.4 D_fit反馈需要如实命名

当前代码没有直接发送私有参考对象，但发送预测及其逐题得分。EM为1可确认该预测属于评分器接受的答案，不能把 `reference_not_sent=True` 理解成“修改器无法获得答案信息”。这属于开发监督，不是 D_select/D_report 泄漏的证据。

建议改成 `raw_reference_objects_not_sent`，并明确 `fit_feedback_can_reveal_accepted_answers`。保留有用的正负开发反馈；依赖角色隔离和独立报告抑制过拟合，不能只删掉成功案例。

## 3. 按顺序修改

### 第一步：免费修复并验收工程缺口

1. **移除按字母序静默截断。** 先验证当前合法查询规模下保留全部有效词的方案；若必须限长，规则、语料统计和删词日志都须冻结。IDF和停用词处理是待比较的检索优化，不自动等同于最小缺陷修复。不要只把字母序前60改成原文前60而继续静默丢条件。所有实验臂使用同一后端版本。
2. **增加答案来源接纳条件。** 宿主绑定最终成功answer调用及其响应；返回答案仅允许预注册的轻量规范化，初版可只去首尾空白。增加独立的 `answer_origin_valid`，接纳和交付必须满足。引用是否合法仍另列，不将无引用弃答等同于来源不合法。收据与缓存版本一起更新；旧结果保留但不能伪装成通过新规则。
3. **停止把声明目标当实测模块归因。** 记录意图模块、实际AST修改函数/常量、可确定的影响模块。跨模块或无法判断的改动保留为 `mixed/unknown`，不进入单模块收益估计。语法diff只说明改动位置，不证明因果。为保留通用程序改写能力，不把合法重构一概拒收。
4. **增加硬编码检查，但明确局限。** 检查新增题号、整题文字、题目到答案映射和异常长常量；它只是预警/拒收规则的一层，不是完整防过拟合证明。不要用禁止所有常量的规则误伤正常提示和配置。

验收包括长查询、人名日期词项、参数绑定、无模型终答、覆盖终答、合法规范化、单模块与跨模块修改等真实边界。不需要付费API。

### 第二步：小范围确认链路，继续使用已用题

先用合成WSL和已有执行轨迹完成回归，再预注册少量已用题的现场机制检查。无需立即重复整套8题两臂两次。

通过条件按发生机会定义：

- 当后续检索确实返回未见、合法且放得进预算的窗口时，该轮阅读实际得到至少一个新窗口。
- 需要保留且未触及公开容量上限的已验证引句能进入最终证据；任何容量省略必须有原因。
- 单轮正文、完整请求、轮数和调用上限均符合冻结配置。
- 若没有出现可接收的新窗口，记为“未验证该机制”，不能当通过。

这只验证信息传递。新增文档、引句数量不能代替正确率，也不能加入终端奖励。若同时采用新检索规则，只能称组合版本链路验收；要声称窗口修复的单因素效果，必须另做保留其余条件的对照。新旧冻结实验均单独存档。

### 第三步：新题比较三个固定流程

| 臂 | 流程 | 作用 |
| --- | --- | --- |
| A | 原问题检索→单轮阅读→回答 | 原始简单基线 |
| B | 查询规划→单轮阅读→回答 | 测量规划的贡献 |
| C | 查询规划→阅读→继续检索/阅读→回答 | 测量后续循环的贡献 |

B、C使用相同规划提示、首轮查询数、初始窗口和阅读/回答契约。可以预注册共享每题每次重复的规划与首轮阅读结果，减少前缀随机差；C不能看到B的终答或评分。记录共享前缀后的物理购买成本，同时估计每臂独立部署的逻辑调用成本，不能混算。

A/B回答规划是否有效，B/C回答后续迭代是否有效。若要进一步区分新检索和反复阅读，才另开固定证据重复阅读对照。不是一开始把全部基线一起跑满。

IRCoT明确将后续检索依赖于已获得的信息，这是设置B/C对照的机制依据；本项目的三臂设计是针对当前混淆提出的实验方案，并非直接复现其论文实验。[IRCoT](https://aclanthology.org/2023.acl-long.557/)

### 第四步：题库、统计和调用预算分别冻结

建议把 MuSiQue 作为可诊断的开发侧轨，按2/3/4跳分层；保留未用 BrowseComp 作为原任务的后续确认。MuSiQue通过组合单跳问题构建多跳任务，适合检查桥接信息是否连通，但其成绩不能证明固定10万文档库的搜索改善。[MuSiQue](https://aclanthology.org/2022.tacl-1.31/)

先选择一个主实验，不同时扩大两个题库。新题优先用于增加独立题目，重复测量限制在事先选定的子集。不要按是否答对挑题；题型、难度配额和替补顺序在评分前冻结。分解答案和支持标记只作本地诊断，不能送给被评模型。共享子问题或证据的题目按组划分。

报告逐题/逐组配对差及区间；多次回答先在题内汇总，再按独立题或相关题组重采样。经典配对bootstrap提供重采样依据，但不能消除开发集偏差、地板效应或单题驱动的收益。[Koehn 2004](https://aclanthology.org/W04-3250/)

确认实验前，根据目标提升及方差范围做样本量/功效规划，不能用8题两次重复给出虚假的精确最小可检出差异。第一批更多新题仍可定位为质量探索，不能预先保证显著。

旧112次上限来自 `8×2×(single 2 + loop 5)`。增加固定3次调用的plan-single后，同8题、各2次最多为 `8×2×(2+3+5)=160`。当前预检代码还限定两臂，必须扩展正式协议和预算推导，不能仅编辑旧JSON。首轮实际约¥1.01不代表新题或代码开发也只有同样成本；费用、调用数和外发数据范围都是独立约束。

### 第五步：再启动真实代码演化

答案来源与改动记录验收后，以固定或轮换选模块为基线开展小规模LLM修改；不要立即主张经验选择有效。开发收益、选择收益和锁定报告收益分开。只有出现跨题、非地板的可重复差异，才值得扩大模块经验或复杂选择器；元重加权继续暂缓。
