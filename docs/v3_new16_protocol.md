## 3. 为什么增加延迟参考路径

旧预检要求本地参考文件已存在；本轮先只取问题，不能为了满足旧接口提前读取答案或填一个占位文件。

现方案在 `reference_acquisition` 中冻结官方来源、解码器版本与每题文本 SHA256，与旧 `references_file` 严格二选一。预检只验证这些公开信息。所有题×臂×重复生成完成、请求账本无未知结果、来源和运行时匹配后，评分器才按冻结来源取得参考答案。只解码目标题，并要求源问题与冻结问题完全一致。

```mermaid
flowchart LR
    I[冻结题号与官方版本] --> Q[只取得问题列]
    Q --> P[冻结三臂与统计方案]
    P --> G[授权后生成全部96个结果]
    G --> F[验证完整生成冻结与账本]
    F --> A[取得并解码目标题参考]
    A --> C[原子保存参考和来源凭据]
    C --> R[本地代理评分及配对报告]
```

参考记录绑定计划、生成冻结、来源、解码器、题号、参考行和各自哈希；缓存恢复重新核对这些字段。取得参考失败不记为答错，也不重新购买生成调用。原本从本地文件评分的旧接口仍保留。

Parquet 列投影仍需元数据读取，不能保证 HTTP 字节完全不含相邻列的密文。实现严格检查 HTTP 206、Content-Range、长度、允许的文件服务域、下载字节上限，记录每段哈希。公布的整文件 SHA 被锁定，但未下载整文件并在本地重算；报告明确标记 `full_file_sha256_verified=false`。[Arrow 列投影说明](https://github.com/apache/arrow/blob/main/docs/source/python/parquet/parquet.rst)

解码与官方固定版本一致：Base64、canary 的 SHA256 循环 XOR、UTF-8；题号不解码。[官方固定版本解码器](https://raw.githubusercontent.com/texttron/BrowseComp-Plus/046949032b0328319cc9a02663a759ec601d9402/scripts_build_index/decrypt_dataset.py)

主指标预注册为内部 answer F1，EM、弃答率、证据来源合法性、逻辑调用和费用分列。不是 BrowseComp 官方模型裁判成绩，也不增加付费评审模型。
