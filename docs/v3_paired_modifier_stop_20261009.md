## 2. 故障在哪里

`网络工作进程 URLError → UnknownProviderOutcome → 根题测量停止 → 配对试跑停止`。

原传输层只保存异常类型，没有保存网络原因分类或HTTP状态；因此无法从现有日志细分DNS、TLS、代理、连接失败等原因，也无法判定供应商是否已执行该请求。没有找到可恢复的本地响应或临时响应文件。进程已退出，未在后台继续消耗。

一次不带密钥、题目或生成请求的HEAD检查得到HTTP 401，说明检查时能连接服务；它不能证明先前请求未执行，也不表示已授权密钥失效。

[官方错误说明](https://api-docs.deepseek.com/quick_start/error_codes/)列出具体HTTP错误处理，但本次只留下URLError，不能反推某一HTTP错误。[Chat Completions公开文档](https://api-docs.deepseek.com/api/create-chat-completion/)中本次未找到按本地请求哈希取回原结果的机制；不能据此凭空构造恢复响应。
