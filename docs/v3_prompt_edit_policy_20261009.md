# 仅提示词与程序编辑：可执行的编辑空间对照

日期：2026-10-09。开发分支 `codex/v3-paper-controls`，独立工作区 `rsi-agent-paper`。已授权真实试跑仍使用experience工作区的`ef870ab`运行源码；本次开发不改变它的输入、运行源码或预算。

## 1. 解决什么研究缺口

实际AST归因只能说明改了哪里，无法保证“仅提示词”条件真的只改提示词。若该条件偷偷修改检索、调用轮数或答案后处理，提示词优化与程序编辑的比较就无法解释。

本次补齐第一阶段P4的编辑空间接口：同一个修改器和演化执行器使用显式 `edit_policy`。`program`保留原有rag.py/rag_core.py程序编辑能力；`prompt_only`只允许声明阶段的CONFIG.prompts字符串变化。不新增优化算法，不限制第一阶段程序编辑主条件，也不把工程通过当成质量收益。

## 2. 两种政策

```json
{"schema":"rag-rsi-edit-policy-1","mode":"program"}
```

```json
{"schema":"rag-rsi-edit-policy-1","mode":"prompt_only","allowed_prompt_stages":["plan","read","answer"]}
```

允许阶段可在预注册时固定为非空子集。阶段列表不能重复或使用未知名字；明确政策不能填null。没有政策字段的旧入口保持原有语义，旧冻结实验仍须用其原源码，不因兼容字段就可以绕过源码哈希。

prompt_only的具体约束：

- rag_core.py字节不变。
- rag.py保留原wrapper的其他AST；CONFIG的其他配置值、类型和顺序不变。
- 仅允许声明阶段的提示字符串增改删，每条至多8,000字符；缺失与空字符串等价，不能用空修改消耗一个假“新行为”。
- CONFIG可用现有json.loads字面量或静态字典，禁止动态计算、重复键、非有限数、歧义或影子绑定。
- 检查源码加载编码，阻止非UTF-8编码声明使静态检查与沙箱实际加载出现差异。常见动态执行及命名空间改写路径拒收，提示字符串里的代码字样仅作为文字处理。

这是明确的编辑范围约束，不是一般Python安全证明。模型生成程序仍通过原WSL隔离执行；硬编码检查、答案来源、资源限制、评分与交付规则继续独立生效。提示词处于允许位置并不意味着可植入开发题答案。

## 3. 执行与恢复

```mermaid
flowchart LR
  P[冻结政策＋父程序＋相同反馈] --> M[LLM返回完整修改]
  M --> R[保存原始提案]
  R --> C[宿主静态范围检查]
  C -->|越界| X[冻结拒收原因，计一次机会]
  C -->|通过| L[原开发常量检查与去重]
  L --> W[原WSL执行和独立评价]
  W --> S[选择锁定与报告]
```

真实出站反馈包含政策；模型配置快照、运行manifest和源码冻结同时绑定它。不能只预检一种政策、实际发送另一种。

每个成功解析的提案产生`steps/N/edit_policy.json`，包含父子完整源码哈希、政策、实际提示阶段变化、是否允许和原因。越界提案不会被归档成可执行子节点，也不进入候选测量，但仍消耗原定机会，不补足成功候选。

断点恢复重新计算允许与拒收收据：缺失、被修改、与原提案不一致均停止，不重新购买。解析失败沿用原来的结构拒收处理；不能把未能解析的提案描述为完成了范围检查。最终报告增加政策与政策拒收数。

## 4. 接口与版本

复用EvolutionRunner，增加事前范围检查；ProgramDeveloper只告知政策，宿主在保存原提案后裁决，保证拒收也有可追踪证据。新live schema4在schema3的显式search/select/report基础上增加必填edit_policy；旧schema1/2/3不接受这个新字段。

当前配对试跑仍绑定schema3和原program能力，不混入新政策。后续正式prompt_only对program对照需另行冻结schema4计划，并保持其他实验条件一致。
